# 规则系统要点总览

CC91 项目通过三层规则文件约束 AI 智能体的输出边界。本文摘录各文件的核心要点，完整内容请见对应文件。

---

## 1. `CLAUDE.md`（Lead 工作协议）

**位置**：项目根目录
**约束对象**：Lead 智能体（即顶层 Claude Code）

### 1.1 团队配置

| 角色 | 启动时机 | 职责 |
|------|---------|------|
| Lead（自身） | 全程 | 需求理解、任务编排、审查、收尾 |
| Developer | 开发阶段 | 全栈实现、测试、Bug 修复 |
| QA | 测试阶段 | 执行测试、回归验证、输出报告 |

### 1.2 5 阶段工作流

1. **Phase 1 理解与规划**：澄清需求 → 拆分任务 → 标记风险
2. **Phase 2 开发**：Spawn developer → 实现并自测 → 跟踪状态
3. **Phase 3 测试**：Spawn qa → 实际运行测试（不接受仅静态分析） → 输出报告
4. **Phase 4 审查**：5 维度审查清单（安全/API/错误处理/质量/测试）
5. **Phase 5 收尾**：状态全 completed → git 提交 → 摘要

### 1.3 阻塞升级机制

- 任一任务阻塞超 30 分钟必须上报
- 阻塞超 2 次未解决 → Lead 调整策略或换路径
- 涉及需求歧义 → 回到 Phase 1 重新确认

### 1.4 审查清单

- [ ] 安全性：输入验证、认证授权、敏感数据保护
- [ ] API 设计：RESTful 规范、错误码与错误体一致
- [ ] 错误处理：边界条件、异常路径、避免吞异常
- [ ] 代码质量：命名、结构、重复逻辑
- [ ] 测试质量：新增逻辑的正向与异常用例

### 1.5 问题跟踪纪律

- 发现 Bug/未完成功能立即写入 `docs/issues.md`
- 修复后立即从文件中**删除该条目**（不保留"已修复"标记）
- `issues.md` 只保留未完成工作

## 2. `.claude/agents/developer.md`（Developer 行为约束）

**约束对象**：Developer 智能体（subagent）

### 2.1 核心职责
- 全栈实现：Spring Boot 后端 + React 前端
- 实现前必读现有代码（避免重复造轮子）
- 实现后必须自测（不接受"应该能跑"）

### 2.2 工作原则
- 先用 CodeGraph 查询符号关系，再写代码
- 测试驱动：先写测试再补实现，或实现后立即补测试
- 改动范围最小化：bug 修复不要顺手重构

### 2.3 完成报告格式
```
- 改动文件清单
- 关键决策说明
- 自测结果（mvn test / npm test 输出）
- 已知遗留问题
```

## 3. `.claude/agents/qa.md`（QA 测试质量红线）

**约束对象**：QA 智能体（subagent）

### 3.1 必须做的测试

- **业务分支测试**：每个 Service 方法的正常路径、异常分支、状态变更、边界条件
- **失败路径测试**：用户不存在、密码错误、账户锁定、权限不足
- **集成测试**：Controller → Service → Repository 全链路

### 3.2 禁止做的测试（红线）

- ❌ 测试框架行为：`@Valid` 注解是否生效、Bean 注入是否成功
- ❌ 测试 DTO 的 getter/setter
- ❌ 测试没有断言的"调用即测试"
- ❌ 重复测试同一分支
- ❌ Mock 一切（包括被测对象本身）

### 3.3 报告格式
```
## 测试报告
- 测试总数 / 通过数 / 失败数
- 覆盖的业务路径清单
- 未覆盖路径及原因
- 失败用例的复现步骤
- 环境信息（JDK、Node、MySQL 版本）
```

### 3.4 强制要求
- **必须实际运行测试**，不接受仅看代码静态分析就下结论
- 测试失败时优先**定位根因**，不要简单 `--no-verify` 绕过
